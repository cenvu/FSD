## Database Implementation

`CatalogDatabase` opens or creates a configurable URL, creates its parent directory, applies `PRAGMA foreign_keys = ON`, immediately verifies `PRAGMA foreign_keys` returns `1`, and applies the architecture-required `busy_timeout = 5000`, `synchronous = NORMAL`, `temp_store = MEMORY`, and `journal_mode = WAL` settings. Access is serialized with a recursive lock; statements are prepared, bound, stepped, and finalized; the connection is closed on deinitialization and failed initialization.

The wrapper exposes typed `DatabaseValue` rows, scalar queries, execution, transactions, last-insert-rowid, current schema version, and the default Application Support path `~/Library/Application Support/FSD/catalog.sqlite3`. No regular-file payload is read.

## Schema Bootstrap and Version Handling

Fresh empty databases apply the bundled canonical schema v4 in a `BEGIN IMMEDIATE` transaction and verify `schema_migrations` contains version 4 before commit. Connection pragmas are applied before the transaction; the equivalent pragmas in the canonical script are omitted only from the transactional execution pass because SQLite rejects safety/journal changes inside a transaction. Rollback is attempted on every bootstrap failure.

Existing schema v4 databases open successfully. A future version, an older unsupported version, a missing version on a non-empty database, or an incomplete migration table fails clearly without silent reinterpretation or destruction. No fake migrations for versions 1–3 were added.

## Snapshot Lifecycle Implementation

`SnapshotID`, `SnapshotStatus`, `SnapshotKind`, `SourceCaseSensitivity`, `NormalizationVersion`, and `SnapshotRecord` are defined in `FSD/Model/SnapshotModels.swift`. `SnapshotRepository` supports:

- creating a volume fixture and a snapshot initially in `scanning`;
- adding exactly the minimal root entry needed by foundation tests;
- reading one snapshot and listing snapshots;
- transitioning `scanning` to `complete`, `complete_with_warnings`, `interrupted`, `cancelled`, or `failed` transactionally;
- rejecting terminal-state reversion and unsupported completion normalization identities.

SQLite remains the final enforcement boundary for root count, status insertion, terminal-state behavior, foreign keys, and all schema constraints. No filesystem enumeration exists.

## SQLite Cleanup Finding

The warnings were caused by temporary test directories being removed while a
`CatalogDatabase` connection still owned the catalog/WAL/SHM vnode. Several
XCTest teardowns set the database reference to nil before the removal defer,
which did not guarantee deinitialization ordering. `CatalogDatabase.close()`
now serializes teardown with database access and calls `sqlite3_close_v2`; the
deinitializer delegates to it. Relevant test teardowns explicitly close before
removing temporary directories, and `CatalogDatabaseTests` proves idempotent
close and closed-use failure.

The final test log contains zero `vnode unlinked while in use` and zero
`invalidated open fd` messages. WAL/SHM files therefore remain governed by a
closed connection before fixture cleanup; production catalog behavior was not
weakened.

## Concurrency Warning Disposition

The three warnings were fixed with small documented ownership boundaries:

- `CaptureCancellationToken`: `@unchecked Sendable` is justified by one locked
  mutable cancellation flag and the same lock used for finalization.
- `SnapshotScanner`: immutable configuration, invocation-local capture state,
  and a lock-serialized catalog.
- `MetadataSearchService`: immutable database reference and request-local search
  state, with all SQLite access serialized by `CatalogDatabase`.

`CatalogDatabase` itself is marked `@unchecked Sendable` with the lock invariant
documented in source. No unsafe unchecked conformance was added without that
invariant. The final build log contains zero non-Sendable warnings.
